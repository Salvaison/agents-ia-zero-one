# BOONO V4.10.4 — LIVE15 Acceptance Shadow — 2026-10-15

## Objet

Etudier quantitativement le gain de latence et le risque de repaint lorsqu'un signal natif 15m LIVE provisoire est considéré comme s'il était déjà validé.

Strictement shadow :
- decisionImpact: false ;
- aucune entrée réelle ;
- aucune sortie réelle ;
- aucun changement d'autorité MCB.

## Deux questions séparées

### 1. ENTRY

Hypothèse :
accepter le signal 15m LIVE comme signal validé uniquement lorsque les autres preuves d'entrée sont déjà prêtes.

Le shadow ne traite donc jamais un point LIVE15 comme une entrée autonome.

Pour créer une hypothèse ENTRY, il exige :
- direction du LIVE15 ;
- cohérence MCB 3m dans cette direction ;
- PM rolling 3m ET 5m alignés ;
- efficiency3m >= 25 % ;
- MF Memory compatible ; si transfert MF requis, rolling PM doit être STRONG_TRANSLATION ;
- timing 3m non SETUP_LATE lorsque son origine est connue ;
- boundary résolue ;
- marché non dormant.

Si l'origine temporelle 3m est absente, le shadow ne fabrique jamais un SETUP_LATE.

Mesures :
- prix et heure de l'entrée hypothétique ;
- minutes gagnées avant la clôture 15m ;
- MFE / MAE avant confirmation ;
- signal finalement confirmé ou repaint ;
- référence de risque : MAE >= 180 USD avant confirmation.

### 2. EXIT

Hypothèse volontairement plus permissive pour tester le danger :
un LIVE15 opposé à une position ouverte est enregistré comme s'il avait autorité de sortie à lui seul.

Ce comportement N'EST PAS actif dans V4.

Mesures entre apparition LIVE et résolution de la bougie :
- terrain adverse qu'une sortie immédiate aurait évité ;
- récupération ultérieure dans le sens de la position qui aurait été manquée ;
- signal confirmé / disparu / opposé ;
- références descriptives 180 USD :
  - prematureRecoveryReference ;
  - avoidedAdverseReference.

Cela permet de tester directement l'hypothèse historique selon laquelle LIVE15 seul serait trop nerveux pour les sorties.

## Cycle de vie d'un signal 15m LIVE

Pour chaque bougie 15m :
- première apparition du signal ;
- prix de première apparition ;
- type UP / DN ;
- nombre d'échantillons où il reste présent ;
- disparitions / réapparitions ;
- flips UP <-> DN ;
- heure de clôture théorique ;
- disponibilité réelle de la bougie confirmée ;
- verdict :
  - CONFIRMED_SAME ;
  - REPAINT_NONE ;
  - REPAINT_OPPOSITE.

La résolution n'est faite que lorsque le CSV MCB15 confirmé contient réellement la bougie, afin de ne pas confondre retard de collecte et repaint.

## Statistiques de départ — 24h au déploiement

Sur 47 bougies ayant affiché au moins un LIVE15 :
- 19 premiers signaux ont confirmé dans le même sens ;
- 28 ont repaint ;
- taux brut de confirmation : ~40.4 % ;
- avance moyenne de première apparition : ~13.0 minutes avant la clôture ;
- 28 bougies ont connu au moins une disparition ;
- 4 bougies ont connu un flip UP/DN.

La persistance change fortement la lecture :
- signal présent >= 80 % de la période observée après première apparition :
  - 20 cas ;
  - ~90 % de confirmation ;
- signal présent < 25 % :
  - 22 cas ;
  - 0 % de confirmation.

Ce résultat initial suggère que le danger principal n'est pas simplement le caractère LIVE, mais la faible persistance intra-bougie. Il reste à vérifier si cette persistance, combinée aux preuves 3m/PM/MF, améliore effectivement les entrées sans créer de faux départs.

## Relation avec la sortie active V4.10

La règle active EXIT_LIVE_SIGNAL_STACK_PROTECTION reste inchangée.

Elle exige simultanément :
- LIVE15 opposé ;
- structure 3m opposée ;
- PM adverse productif ;
- perte/rejet MA200 3m.

Le nouveau shadow teste séparément ce qui se serait passé si le LIVE15 seul avait eu autorité de sortie.
