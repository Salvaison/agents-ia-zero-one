## 1. Capture MarketCipher isolée sur TA

Avant :
- boono-desk-capture se connectait toutes les 10 s au même target CDP que le collecteur 3m ;
- Page.captureScreenshot était appelé sur l'onglet 2AqpEMfD interval=3 ;
- le glitch visible toutes les 10 s coïncidait exactement avec la cadence de capture.

Après :
- capture exclusivement sur le layout TA qljTf3vu ;
- refus explicite du layout collecteur 2AqpEMfD ;
- changement 3m/15m via TradingView setResolution(), sans reload ;
- state runtime expose captureIsolation: TA_ONLY.

Conséquence :
- les onglets collecteurs ne sont plus touchés par Page.captureScreenshot ;
- l'onglet TA devient de fait la surface de capture pendant que le daemon tourne ;
- si l'utilisateur change manuellement son timeframe, le daemon le remettra au timeframe de capture au cycle suivant.

Contrôle après activation :
- capture 10 s active ;
- aucun gap 3m sur les deux dernières heures contrôlées ;
- heartbeats collecteurs frais.

## 4. Correction setupTs=null -> 0

Bug introduit avec la préservation d'identité causale V4.10.1.

Ancienne condition :
Number.isFinite(Number(previousSetup.setupTs))

Or :
Number(null) === 0.

Un OBSERVE portant la même setupKey pouvait donc produire :
- setupTs = 0 ;
- setupId suffixé @0 ;
- preuve POST_SETUP calculée depuis l'origine des données.

Correction :
- timestamp précédent accepté uniquement s'il est non-null, non-vide, fini et >0 ;
- sinon un nouveau setupTs causal = marketTimestamp courant ;
- setupId régénéré avec ce timestamp.

Test de régression ajouté.
