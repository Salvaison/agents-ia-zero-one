# V4.6 — Structural trajectory contract — 2026-10-05

## Statut

Version moteur : `v4.6-structural-trajectory-20261005`.

Cette version corrige la confusion historique entre :
- **position dans le lobe** : où se trouve LBW par rapport à zéro ;
- **trajet structurel E→E** : direction causale persistante entre extrema confirmés.

Principe central :

> **Le lobe indique où se trouve la vague ; E→E indique où elle va.**

Le module commun est :
`modules/v4/layers/structural-trajectory.js`.

## Causalité

Les extrema LBW sont confirmés uniquement après des barres ultérieures :

- 3m : 1 barre de confirmation ;
- 15m : 2 barres ;
- 1h : 2 barres ;
- 4h : 2 barres ;
- Daily : 1 barre ;
- Weekly : 1 barre.

Le trajet reste actif jusqu'au pivot causal opposé. Une respiration locale ou un changement de pente instantané ne retourne pas à lui seul la direction structurelle.

## Rôle par timeframe

### 1h — contexte
`primaryRelation` utilise maintenant `structuralDirection`, et non plus le signe du lobe / direction locale legacy.

La lecture legacy reste conservée dans `legacyDirection` et `legacyPrimaryRelation` pour audit.

### 15m — thèse
La thèse 15m conserve sa capacité à détecter un `REVERSAL_FORMING` avant la confirmation complète du prochain pivot structurel.

Si un trajet E→E causal est déjà confirmé et s'oppose au lobe courant, il peut proposer une candidate `STRUCTURAL_TRAJECTORY`.

Il ne crée jamais directement une entrée : 3m + PM doivent encore maturer l'opportunité.

### 3m — timing
La cohérence 3m utilise d'abord `structuralDirection`.

États :
- `STRUCTURAL_ALIGNED`
- `STRUCTURAL_OPPOSING`

Le `turningDirection` puis le signe du lobe ne servent que de fallback si aucune trajectoire E3→E3 n'est encore disponible.

### 4h / Daily / Weekly
Même contrat structurel, mais rôle décisionnel inchangé : qualification shadow.

Weekly peut exposer `structuralDirection=null` lorsque l'historique disponible ne contient pas encore un pivot causal suffisant.

## Structural handoff

Le shadow `structural-handoff-shadow-v0.1` utilise :
- 1h structural = contexte ;
- 15m thesis = campagne ;
- 3m structural = timing.

Il reste `decisionImpact=false`.

Le contrat anti-churn reste inchangé :
`proofStartTs = max(handoffTs,lastExitTs)`.

PM / ticker / efficiency pré-sortie ne sont jamais recyclés pour une ré-entrée.
