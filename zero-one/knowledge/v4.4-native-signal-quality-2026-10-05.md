# BOONO V4.4 — signal MCB renforcé, qualité de marché et matérialité post-setup — 05/10/2026

## Décisions validées

V4.4 corrige les défauts observés sur les huit trades V4.3 du 04→05/10 :

1. un marché improductif ne doit plus laisser passer facilement de petites structures MCB ;
2. la preuve post-setup ne peut plus être validée par un net simplement du bon signe avec une conversion quasi nulle ;
3. le signal natif MCB `UP` confirmé sous `-60` devient un événement renforcé asymétrique ;
4. ce `UP_REINFORCED` peut contourner la résistance du background 1H pour un LONG, sans inventer de `DN_REINFORCED` symétrique ;
5. un retournement 3m déjà accompli et transformé en lobe aligné ne doit plus être rejeté au seul motif que `turningDirection` est revenu à null.

## LOW_EDGE + qualité MCB

Le marché est qualifié `LOW_EDGE` lorsque la fenêtre 60m combine :
- efficacité <= 12 % ;
- flips >= 35/h.

Dans ce cas :
- une relation MCB sub-80 reste `OBSERVE` ;
- une paire majeure `PAIR_MAJOR_QUALITATIVE` peut encore armer un setup ;
- `UP_REINFORCED` peut également contourner ce filtre pour un LONG.

Le seuil 80 reste donc qualitatif et conditionnel : il n'est toujours pas un veto global.

Contre-factuel sur #3/#4/#5 de la séquence utilisateur (#57/#58/#59 système) :
- tous trois deviennent `OBSERVE` via `LOW_EDGE_REQUIRES_MAJOR_MCB_OR_REINFORCED_UP`.

## Matérialité PM post-setup

Pour une preuve d'entrée construite après `setupTs`, `TRANSLATING` exige désormais :
- |netSinceSetup| >= 10 USD ;
- efficiencySinceSetup >= 25 %.

Sinon :
- gross important + bon signe mais mauvaise conversion → `COMBAT_ALIGNED` ;
- symétriquement `OPPOSITE_COMBAT` dans l'autre sens.

Le dernier tick n'est plus souverain une fois un setup armé : la traduction d'entrée est portée par le cumul causal depuis `setupTs`.

Cas #6 utilisateur (#60 système) :
- net -3.1 ;
- gross 57.3 ;
- efficacité ~5 % ;
→ `COMBAT_ALIGNED`, donc pas d'entrée malgré un dernier burst vendeur.

Cas #7 / #8 :
- #7 : +20 / 33, ~61 % → passe ;
- #8 : -29.7 / 34.5, ~86 % → passe.

## Signal MCB natif renforcé

Nouveau module `native-signal.js`.

`UP_REINFORCED` :
- signal natif MCB `wt1_cross_up` confirmé ;
- valeur <= -60 ;
- âge max 90 min ;
- pas invalidé par un DN plus récent.

Aucune symétrie artificielle :
- pas de `DN_REINFORCED` à +60.

## Bypass LONG contre 1H

Si `UP_REINFORCED` est actif dans le creux 15m courant :
- il crée une candidate LONG MCB exceptionnelle même si le 1H est encore AGAINST_BACKGROUND ;
- il ne bypass pas la cohérence locale 3m ;
- il ne bypass pas les limites structurelles ;
- il ne transforme pas directement le signal en ordre.

Voie accélérée :
- UP_REINFORCED ;
- setup local cohérent ;
- preuve fraîche depuis setup :
  - net LONG >= +50 USD ;
  - efficacité >= 12 % ;
→ entrée LONG autorisée même si ticker / 1H ne sont pas encore revenus en confirmation complète.

Contre-factuel sur le signal renforcé du 05/10 ~07:15 Paris :
- setup au signal ;
- première entrée LONG théorique vers 07:34 Paris @ ~85 562 ;
- le système précédent avait attendu / refusé à cause du background 1H.

## Mémoire du turn 3m

Pour une candidate contre le 1H :
- `TURN_ALIGNED` reste valide ;
- un lobe 3m déjà aligné, commencé après l'extrême 15m, est désormais traité comme `ESTABLISHED_ALIGNED_AFTER_EXTREME` implicitement via `alignedAfterExtreme`.

Le système ne perd donc plus la preuve juste parce que `turningDirection` redevient null après que le turn a réussi.

## Protection de sortie par signal natif

- Un `UP_REINFORCED` confirmé après l'entrée d'un SHORT déclenche `EXIT_NATIVE_STRONG_SIGNAL` immédiatement.
- Un UP/DN natif standard après entrée peut déclencher `EXIT_NATIVE_SIGNAL_PROTECTION` si :
  - il s'oppose à la position ;
  - le 3m va dans ce sens opposé ;
  - net3m PM confirme ce même sens.

Cela donne enfin aux signaux natifs MCB un rôle dans les sorties sans les transformer tous en ordres automatiques.
