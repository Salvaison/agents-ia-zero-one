# BOONO V4.2 — Neutralité de transition, maturité PM/3m et sizing réel — 03/10/2026

## Validation

Benjamin valide une correction ciblée du churning démontré, sans réintroduire les empilements de veto de V3.

Principe actif :

```
MCB détecte une transition
→ TRANSITION_NEUTRAL / observation
→ net3m réellement aligné + cohérence MCB 3m
→ LONG_FORMING / SHORT_FORMING
→ PM réellement TRANSLATING + ticker confirmé
→ entrée
```

Aucun délai fixe n'est introduit. Un retournement brutal peut donc mûrir en un seul cycle si les preuves sont déjà présentes.

## 1. TRANSITION_NEUTRAL

Avant V4.2, `REVERSAL_FORMING` donnait immédiatement une direction tradable `LONG_FORMING` / `SHORT_FORMING`.

V4.2 sépare maintenant les étapes :

- `TRANSITION_NEUTRAL · REVERSAL_FORMING`
  - direction candidate connue ;
  - aucune direction actionable ;
  - ticker ne peut pas confirmer une entrée ;
- si maturité validée :
  - `LONG_FORMING` ou `SHORT_FORMING` ;
- une structure E15 qualitativement majeure déjà établie peut conserver `LONG` / `SHORT`.

Les extensions sub-80 passent également par la neutralité avant de devenir une thèse FORMING.

## 2. Porte de maturité sans minuterie

Promotion de la candidate seulement si :

1. `net3m` est réellement dans le sens de la candidate ;
2. le MCB 3m est cohérent :
   - lobe 3m dans le même sens, ou
   - turningDirection dans le sens candidat ;
   - un turningDirection opposé maintient la neutralité.

La maturité est informationnelle et causale, pas chronométrique.

## 3. PM Live : BURST != TRANSLATION

Avant V4.2, une dernière impulsion locale suffisamment grande pouvait produire `TRANSLATING` même si le déplacement net 3m allait dans le sens opposé.

Depuis V4.2 :

- dernière impulsion alignée + net3m aligné + seuil PM atteint
  → `TRANSLATING` / `STRONG_TRANSLATION`;
- dernière impulsion alignée mais net3m non aligné
  → `BURST_ALIGNED`;
- symétriquement, une impulsion opposée sans net3m opposé devient `OPPOSITE_BURST`.

Ainsi PM ne confond plus une poussée ponctuelle avec une traduction réellement acquise sur 3 minutes.

## 5. Dimensionnement repris du vieux BOONO

Le vieux moteur actif encode réellement :

- capital : 1000 USD ;
- positionPercent : 15 % ;
- marge engagée : 150 USD ;
- levier : x10 ;
- notionnel : 1500 USD ;
- stop structurel absolu en déplacement BTC : 500 USD.

Formule historique exécutée :

```
pnlUsd = pnlPrixPct / 100 × notionnel
```

À BTC ~84–87k, un mouvement adverse de 500 USD coûte environ 8.6–8.9 USD sur 1500 USD de notionnel, donc reste sous la limite visée de ~10 USD = 1 % d'un capital de 1000 USD.

V4.2 reprend ce modèle en paper trading et stocke désormais :

- `capitalUsd = 1000`
- `marginUsd = 150`
- `notionalUsd = 1500`
- `positionPercent = 15`
- `leverage = 10`
- `pnlUsd`
- `currentPnlUsd`
- `mfePnlUsd`
- `maeLossUsd`
- `riskAt500PriceMoveUsd`

Exemple trade #16 :
- +24.181 % sur marge ;
- marge 150 USD ;
- PNL simulé = +36.27 USD ;
- risque d'un déplacement adverse de 500 USD à son prix d'entrée = ~8.67 USD.
